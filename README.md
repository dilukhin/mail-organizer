# mail-organizer

Лёгкая безопасная система организации Gmail и Outlook/Hotmail: серверные правила, детерминированная классификация, сроки хранения, аудит и факультативная ИИ-классификация.

## Зачем проект

Почтовые ящики со временем превращаются одновременно в архив документов, поток служебных уведомлений, хранилище чеков и билетов, канал кодов подтверждения, подписки и рекламу. Цель `mail-organizer` — разделить эти роли и сделать обработку предсказуемой:

- важное остаётся доступным и защищённым;
- массовый поток сортируется на сервере провайдера;
- временные классы имеют понятный срок жизни;
- автоматические действия проверяются и журналируются;
- ИИ помогает только там, где обычных правил недостаточно;
- отказ ИИ не останавливает основную систему.

## Архитектурные принципы

```text
Gmail filters ─────┐
                   ├──> mail-organizer на VPS ──> safety gate ──> Gmail API / Microsoft Graph
Outlook rules ─────┘            │
                                ├── deterministic policy
                                ├── retention
                                ├── SQLite state/audit
                                └── optional AI adviser

ChatGPT Work ───────────────────────> периодический аудит, анализ ошибок,
                                     крупные разовые операции и подготовка policy changes
```

1. **Server-first.** Стабильные простые правила по возможности исполняются Gmail и Outlook до VPS.
2. **Deterministic-first.** Известные отправители и шаблоны обрабатываются без ИИ.
3. **AI-optional.** ИИ — советник для неизвестных и спорных случаев, а не исполнитель.
4. **Work-assisted operations.** ChatGPT Work используется как верхний человеко-управляемый уровень для периодического аудита, анализа сложных выборок, подготовки изменений правил и крупных разовых операций. Work не является частью 24/7 runtime и не должен быть необходим для обычной сортировки.
5. **Safety-first.** Любая запись проходит `inspect → expected_state → atomic action → read-back verify`.
6. **Dry-run-first.** Новая возможность сначала наблюдает и предлагает действия, затем получает минимальные обратимые права.
7. **No permanent delete.** Программа не должна безвозвратно удалять письма; максимальное автоматическое действие — перемещение в корзину после отдельного retention gate.
8. **Untrusted mail.** Текст письма, HTML, ссылки и вложения считаются недоверенными данными и никогда не становятся инструкциями для агента или модели.
9. **Minimal data.** На VPS не создаётся полный архив почты; сохраняются только необходимые идентификаторы, курсоры, решения и журнал действий.

## Уровни системы

Проект сознательно разделяет штатный runtime и средства интеллектуального обслуживания:

1. **Gmail/Outlook server rules** — основной быстрый слой сортировки.
2. **`mail-organizer` на VPS** — синхронизация, сложная policy, retention, safety и журнал.
3. **Модели через API** — факультативная классификация неизвестных случаев и точечная эскалация.
4. **ChatGPT Work** — периодический аудит и крупные управляемые задачи: разбор ошибок классификации, поиск новых массовых типов писем, анализ исторической почты, подготовка изменений policy и планов миграции.
5. **Codex/OpenCode** — разработка и техническое обслуживание кода, но не штатный исполнитель почтового потока.

Отключение уровней 3–5 не должно останавливать базовую работу уровней 1–2.

## Целевая среда

Проект рассчитан на недорогой Linux VPS примерно класса 1 vCPU / 1 ГБ RAM. Основной исполнитель должен быть небольшим и короткоживущим: задания `systemd timer`, Python и SQLite. Swap рассматривается как страховка от пиков, а не как основание для тяжёлого постоянно работающего агента.

Точные адреса серверов, OAuth-секреты и другие эксплуатационные секреты в публичном репозитории не хранятся.

## Что планируется

### v0.1 — только чтение и dry-run
- инвентаризация Gmail/Outlook;
- чтение существующих ярлыков, папок и правил;
- инкрементальная синхронизация;
- SQLite для курсоров и журнала;
- декларативная policy;
- детерминированная классификация;
- отчёт «что было бы сделано» без изменения почты.

### v0.2 — обратимые изменения
- назначение категорий/ярлыков;
- архивирование и безопасное перемещение;
- управление только `managed` server rules;
- `plan → apply → read-back`;
- защищённый Gmail Control Queue.

### v0.3 — факультативный ИИ и аудит
- структурированная классификация неизвестных сообщений;
- пороги уверенности и `REVIEW_REQUIRED`;
- эскалация сложных случаев на более сильную модель;
- периодический аудит качества;
- ChatGPT Work для крупных управляемых аудитов и подготовки policy changes;
- отсутствие прямых write-инструментов у модели.

### v0.4 — сроки хранения и миграция
- retention engine;
- сначала dry-run, затем перемещение просроченного в корзину;
- protected/hold-классы;
- постепенная миграция старой почты и исторических папок;
- Work может использоваться для анализа и планирования крупных миграционных проходов, но выполнение остаётся за проверяемыми инструментами `mail-organizer`.

Подробные переходные критерии описаны в [ROADMAP.md](ROADMAP.md).

## Управление правилами

Источник истины для правил, которыми управляет проект, должен находиться в Git:

```text
policy/
├── categories.yaml
├── rules.yaml
├── retention.yaml
├── protected.yaml
└── control-queue.yaml
```

Существующие пользовательские Gmail/Outlook rules по умолчанию считаются внешними (`external`) и не изменяются. Правило становится `managed` только после явного принятия под управление.

Планируемый интерфейс:

```text
mailctl policy plan
mailctl policy apply
mailctl sync --dry-run
mailctl retention --dry-run
mailctl audit
```

## Безопасность

Проект использует подход `agent-safe`:

```text
classify
→ inspect
→ expected_state
→ checkpoint/rollback
→ execute one atomic action
→ verify actual state
→ continue / recovery
```

Неожиданный результат — причина остановить исходную операцию и перейти к диагностике, а не повод автоматически «исправлять» состояние дополнительными опасными командами.

Управляющая почтовая очередь (`ChatGPT-Control/...`) является отдельным защищённым контуром. Само наличие специальной темы письма не является достаточной авторизацией команды.

ChatGPT Work подчиняется тем же safety-ограничениям: крупная задача через Work не является основанием обходить `dry-run`, `plan`, blast-radius limits, protected scope и read-back verification.

Подробнее: [docs/SECURITY_MODEL.md](docs/SECURITY_MODEL.md).

## Разработка

- язык общения, документации, комментариев и пользовательских журналов — русский;
- GitHub Connector — основной удалённый транспорт для ChatGPT Web;
- минимизировать зависимости и фоновые процессы;
- не добавлять универсальный ИИ-агент в штатный runtime без доказанной необходимости;
- ChatGPT Work использовать для периодического обслуживания и крупных управляемых задач, а не как обязательный постоянный runtime;
- тестировать ядро без доступа к реальной почте и без вызова ИИ;
- секреты, рабочая SQLite и эксплуатационные данные не коммитить.

Инструкции для агентов: [AGENTS.md](AGENTS.md).

Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Статус

Репозиторий находится на стадии начального проектирования. Первый практический этап — **v0.1 read-only + dry-run**. До его завершения проект не должен изменять сообщения, папки или серверные правила реальных ящиков.
