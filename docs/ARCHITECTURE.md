# Архитектура

## 1. Назначение

`mail-organizer` организует два существующих почтовых ящика — Gmail и Outlook/Hotmail — без создания отдельного локального почтового архива. Основная сортировка должна быть серверной и детерминированной. VPS дополняет её там, где штатных правил провайдеров недостаточно: инкрементальная синхронизация, сложная policy, сроки хранения, аудит и факультативная ИИ-классификация.

ChatGPT Work используется как отдельный верхний уровень периодического обслуживания: крупные аудиты, анализ ошибок, разбор исторической почты, подготовка изменений policy и управляемые разовые операции. Work не входит в 24/7 runtime и не должен быть необходим для обычной сортировки.

## 2. Компоненты

```text
                  Gmail                         Outlook
                    │                              │
             server filters                 message rules
                    │                              │
                    └──────────────┬───────────────┘
                                   │
                             mail-worker
                                   │
                 ┌─────────────────┼────────────────┐
                 │                 │                │
              policy           safety gate       state
                 │                 │                │
          deterministic       plan/apply/       SQLite
          classifier          read-back
                 │
                 └──────── optional AI adviser

                         ChatGPT Work
                              │
                  periodic audit / analysis
                  policy proposals / migrations
                              │
                              └──> только через те же safety gates
```

### Почтовые провайдеры
Хранят исходные письма и выполняют простые стабильные правила. Проект не должен дублировать полный mailbox на VPS.

### `mail-worker`
Короткоживущий процесс, запускаемый `systemd timer`. Получает только изменения с последней синхронизации, вычисляет решения и завершает работу.

### `mailctl`
Административный CLI: inventory, dry-run, policy plan/apply, audit, retention dry-run, status.

### Policy
Декларативные файлы в Git — источник истины только для правил, которыми проект явно управляет. Исторические пользовательские правила по умолчанию `external`.

### SQLite
Хранит provider cursors, минимальные message metadata, решения, факты действий, expected/actual state и incidents. Тело письма не является нормальной частью базы.

### AI adviser
Изолированная функция классификации неизвестных случаев. Не имеет инструментов изменения почты или системы.

### ChatGPT Work
Человеко-управляемый верхний уровень для задач, которые нецелесообразно выполнять на каждом письме:
- анализ выборки ошибок классификации;
- поиск новых массовых отправителей и шаблонов;
- подготовка новых/изменённых правил;
- анализ исторических папок и планирование миграции;
- крупные разовые аудиты состояния Gmail/Outlook/VPS/GitHub.

Work не заменяет `mail-worker`, не является scheduler и не становится отдельным постоянным control-plane. Любые предлагаемые или выполняемые через Work изменения должны проходить те же `plan → expected_state → bounded action → read-back` ограничения, что и обычные административные операции.

### Codex/OpenCode
Инструменты разработки и технического обслуживания кода. В штатном runtime VPS не требуются.

## 3. Поток нового сообщения

1. Почтовый сервер применяет собственные фильтры.
2. `mail-worker` получает изменение инкрементально.
3. Проверяется protected/control scope.
4. Применяется детерминированная policy.
5. Если решения нет, случай передаётся ИИ либо получает `REVIEW_REQUIRED`.
6. Safety gate проверяет допустимость предложенного действия.
7. В dry-run действие только журналируется.
8. В write-mode выполняется одна атомарная операция.
9. Состояние перечитывается через API и сравнивается с `expected_state`.
10. Расхождение переводит соответствующую операцию в recovery/stop.

ChatGPT Work не участвует в этом per-message hot path.

## 4. Server rules и managed policy

Не все правила должны жить на VPS.

**На сервер провайдера:** известные отправители/домены, устойчивые темы, однозначные сервисные уведомления, безопасное автоматическое архивирование.

**На VPS:** сложные комбинации, retention, cross-provider policy, protected/hold, аудит, ИИ и контроль конфликтов.

**В ChatGPT Work:** анализ и подготовка изменений, которые затем выражаются через reviewed policy, `mailctl` или ограниченную управляемую операцию. Work не должен становиться скрытым альтернативным источником истины для правил.

`mailctl policy plan` сравнивает желаемое managed-состояние с фактическим. `apply` разрешён только после plan и выполняет read-back.

## 5. ИИ

ИИ не является control-plane. Его контракт похож на чистую функцию:

```text
sanitised_message_features -> structured_classification
```

Минимальный результат:
- category;
- confidence;
- retention_class;
- needs_action;
- reason_code.

Никакие инструкции внутри сообщения не должны менять system/policy. Модель не получает shell, SMTP/send, Gmail/Graph write или произвольный web.

При недоступности ИИ deterministic core продолжает работу.

Модельный routing может использовать разные модели по стоимости и сложности. Более сильные модели и ChatGPT Work предназначены преимущественно для эскалации сложных случаев на уровне аудита, а не для постоянной обработки каждого письма.

## 6. Retention

Retention — отдельный механизм от классификации.

```text
age > retention
AND not protected
AND not hold
AND not action_required
AND confidence/policy sufficient
→ candidate for Trash
```

Включение проходит отдельный dry-run период. Permanent delete не является функцией проекта.

Work может анализировать кандидатов и ошибки retention, но не отменяет требования к dry-run и protected scope.

## 7. Control Queue

Существующая Gmail-структура `ChatGPT-Control/Commands`, `Responses`, `Processed` учитывается как специальный защищённый канал.

Требования:
- исключить из обычной классификации и retention;
- whitelist операций;
- проверять разрешённого отправителя и техническую аутентификацию;
- subject/prefix сам по себе не авторизует действие;
- опасные массовые операции через почтовую команду не разрешать;
- команды управления отделить от текста обычного письма.

## 8. Развёртывание

Базовый runtime:
- Linux VPS;
- отдельный пользователь `mailbot`;
- Python;
- SQLite;
- systemd services/timers;
- OAuth credentials с минимальными scopes.

Не требуются по умолчанию: Docker, Redis, PostgreSQL, брокер сообщений или постоянно работающий агент.

ChatGPT Work находится вне VPS runtime и используется по необходимости из ChatGPT Web.

## 9. Границы доверия

1. **Письмо:** недоверенные данные.
2. **ИИ:** недоверенный советник, результат проходит валидацию.
3. **ChatGPT Work:** мощный управляемый оператор/аналитик, но не исключение из safety-policy.
4. **Policy из reviewed Git:** доверенная конфигурация.
5. **Почтовый API:** внешний state; каждую запись проверять read-back.
6. **VPS:** минимально привилегированная среда; секреты вне Git.
7. **GitHub:** источник версии кода/policy, но не хранилище пользовательской почты.
